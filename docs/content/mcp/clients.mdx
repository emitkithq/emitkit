Clients that sign in with OAuth, such as ChatGPT, Claude and Claude Code,
need only the server URL: see [Connect with OAuth](/integrations/oauth). Any
client that can send a custom request header can use an
[API key](/api/api-keys) for the Project the agent should write to instead.

## Claude Code with an API key

```bash
claude mcp add --transport http emitkit https://api.emitkit.com/mcp \
  --header "Authorization: Bearer emitkit_REPLACEWITHKEY"
```

## Other clients

Most clients accept a JSON server entry like this:

```json
{
  "mcpServers": {
    "emitkit": {
      "type": "http",
      "url": "https://api.emitkit.com/mcp",
      "headers": {
        "Authorization": "Bearer emitkit_REPLACEWITHKEY"
      }
    }
  }
}
```

A request without credentials, or with a wrong key, is rejected with `401` and
a `WWW-Authenticate` header that points OAuth clients at EmitKit's sign-in.
EmitKit checks the credential on every request, so a wrong key already fails
when the client connects: if it can't connect, check the key.
