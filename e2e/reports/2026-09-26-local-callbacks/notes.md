# Notes: callbacks (local)

Run against `pnpm dev` (PORT=5391) with migration `0008_event_card_callback.sql` applied (`pnpm db:migrate:local`). Scenarios: `01-routing`, `02-public-api`, `04-dashboard`, `11-channels`, `19-actions`. 51 passed, 2 skipped (the paywall-only cases; billing is off locally). Run on main + this branch after the review fixes, with `global_fetch_strictly_public` on in `wrangler.jsonc` (the local receiver on 127.0.0.1 is still reached).

- The callback tests start a receiver on `127.0.0.1` inside the test process, so they only run against a local dev server. It answers 500 to the first POST: the retry arrives about 10 s later with the same `webhook-id`, and both deliveries verify with the `standardwebhooks` library (the one receivers use) and the secret from `projects/callbackSecret`. `GET /v1/events/{id}` then reports `callback: { attempts: 2, lastStatus: 200, deliveredAt }`.
- Expiry is real time: a question with `expiresIn: 10` calls back once with `event.expired`, and nothing follows in the next 5 s. Miniflare honours the queue's `delaySeconds`, so the delay path is the same one production runs.
- `callbackUrl` validation: only on events that wait, never at EmitKit's own hosts (also with a trailing dot or another port), `https` unless the deployment itself is `http` (dev allows `localhost`, `*.localhost` and `127.0.0.1`). `resume` never reaches the answer page or the dashboard feed.
- Settings → API keys: an owner reveals the project's signing secret; the test compares it with the RPC's without printing it, and the screenshot (`screenshots/19-actions-an-owner-reveal-*`) masks it. Another organization asking for the project's secret by id gets 404 and no `whsec_`. Members don't see the block and the RPC requires an owner or admin (`requireManager`); that case is not automated here.
- Not automated: the backstops that need a failing queue (an answer whose callback couldn't be queued gets it at the expiry check; a rerun attempt counts once and never resends a delivered callback), the backoff past the first retry (30 s … 8 h) and the chained expiry for `expiresIn` over a day (Queues' delay is at most 86,400 s, so the check re-queues itself). Both are the same code path with a longer delay.
- Secrets: the report's redaction replaces `whsec_…`, API keys, cookies and `"secret"` fields in logs and traces. Traces no longer record screencast frames (`playwright.config.ts`): a frame is a picture of the screen, and one taken after a reveal showed the secret. Checked: no `.jpeg` in any trace, no unredacted `whsec_` or `emitkit_` key.
