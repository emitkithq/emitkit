# Notes: actions and fields (local)

Run against `pnpm dev` (PORT=5391) with migration `0007_event_card.sql` applied (`pnpm db:migrate:local`). Scenarios: `01-routing`, `02-public-api`, `04-dashboard`, `11-channels`, `19-actions`.

- `19-actions` covers the API, validation messages, answering over the dashboard RPC, first-answer-wins, cancel, expiry (a real 10 s wait), links-only events, project and organization isolation, idempotent retries, MCP (including that the `createEvent` tool schema equals `openapi.json`'s `CreateEventRequest` for `fields`, `actions`, `expiresIn`), error codes, and the answer page in Chrome at 390×844 (the `requires` error is scrolled into view and focused; the outcome after answering). Screenshots: `screenshots/19-actions-the-answer-page-*`.
- Not automated: the push opening `/a/{id}`. Web Push needs a public HTTPS origin (see `05-push-pwa`); the URL change is in `Notifications.deliver` (`waits` on the queue message).
- `19-actions` also drives the one-tap single choice, the implied Send (`submit`, "… answered"), and the dashboard feed ("Waiting for an answer", links, the Answer button opening `/a/{id}`). Other states of the answer page (every control, conflict, canceled, expired, not found, dark mode) were checked by hand in Chrome at 390×844 while building it.
- Environment: running `pnpm build` while `pnpm dev` is up rewrites Vite's dependency cache and the dev server then answers 504 for stale modules ("Something went wrong" on every page). Restart `pnpm dev` (and remove `node_modules/.vite`) after a build before running scenarios.
- Rate limit, checked by hand before the fix: a fresh key polling `GET /v1/events/{id}` once per second got `429` on request 101 (99 × 200, then 429 with `Retry-After: 59`), because Better Auth only reset the count after 60 idle seconds. With `patches/@better-auth__api-key@1.7.5.patch` the same run gives 110 × 200. `02-public-api` now pins it ("a steady client gets a fresh window every minute", about 60 s).
